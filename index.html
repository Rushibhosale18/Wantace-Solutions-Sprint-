2. Forensic Evidence Audit & Data Inconsistency Ledger

A rigorous audit of the client's raw order sheet and WhatsApp export reveals structural failure points. Every finding is classified according to evidentiary certainty:

Concrete Evidence Evidence Class Operational Root Cause System Solution (Phase 1)
Gupta Traders (200 Kadai): Appears twice—once Dispatched, once Pending. Reported Inconsistency Untracked Split Dispatch: 100 pcs were fulfilled, and the remaining 100 pcs were re-entered as a new pending row. Creates high risk of duplicate production. Parent-child order dispatch schema with automated balance decrementing.
Jain Crockery (150 Kadai): Exact duplicate row present in intake sheet. Inferred Duplicate No Idempotency Check: Order received on WhatsApp and entered twice during manual reconciliation. Central unique Order IDs (ORD-YYYY-XXXX) with duplicate entry detection.
Order with Blank Customer: Quantities noted, but customer field is NULL. Observed Fact Hasty Manual Entry: Copied from a rushed voice note without mandatory header validations. Mandatory form validation: customer_id and product_id are strictly non-nullable.
Pending Order in "kg" without Rate: Metal weight logged; unit rate empty. UoM Mismatch Cookware is stamped from steel sheets (kg) but sold per piece. Blocks automated billing. Dual-UoM master catalog: standard piece-to-weight nominal conversions.
Sharma Order Held at Gate: Boxed cookware halted at exit gate for past dues. Process Failure Credit check occurs at dispatch gate instead of order booking, locking up working capital. Automated "Payment Hold" status triggered at order booking if client exceeds credit limit.
Negative Quantity Row (-15 pcs): Recorded directly in forward sales register. Ad-hoc Workaround Absence of RMA / Return workflow; staff using forward sales sheet to track returns. Dedicated Sales Return module with condition triage (Scrap vs Polish vs Restock).
Outsourced Polishing: 420 kg sent; 1,180 pcs returned; 6 kg shortage flagged. Needs Confirmation 420 kg / 1,180 pcs = 355.9g/pc. Without nominal standards, 6 kg scrap vs theft cannot be resolved. Job-Work Challan module tracking weight sent, piece yield, and scrap % tolerance.

4. Production PostgreSQL Relational Schema & DDL

-- 1. Customers Table (with credit gatekeeping)
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    business_name VARCHAR(150) NOT NULL,
    contact_phone VARCHAR(20) NOT NULL,
    credit_limit NUMERIC(12, 2) DEFAULT 0.00,
    outstanding_balance NUMERIC(12, 2) DEFAULT 0.00,
    is_credit_hold BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. Central Orders Table
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INT NOT NULL REFERENCES customers(customer_id) ON DELETE RESTRICT,
    order_number VARCHAR(50) UNIQUE NOT NULL, -- e.g. ORD-2026-0042
    order_date DATE NOT NULL DEFAULT CURRENT_DATE,
    promised_date DATE NOT NULL,
    stage_status VARCHAR(30) NOT NULL CHECK (
        stage_status IN ('ORDER_BOOKED', 'PAYMENT_HOLD', 'IN_PRODUCTION', 'AT_POLISHER', 'READY_FOR_DISPATCH', 'PARTIALLY_DISPATCHED', 'COMPLETED')
    ),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 3. Order Items with UoM Nominal Conversions
CREATE TABLE order_items (
    item_id SERIAL PRIMARY KEY,
    order_id INT NOT NULL REFERENCES orders(order_id) ON DELETE CASCADE,
    product_name VARCHAR(100) NOT NULL,
    uom VARCHAR(10) NOT NULL CHECK (uom IN ('PCS', 'SET', 'KG')),
    quantity_ordered NUMERIC(10, 2) NOT NULL CHECK (quantity_ordered > 0),
    quantity_dispatched NUMERIC(10, 2) DEFAULT 0.00 CHECK (quantity_dispatched >= 0),
    nominal_weight_per_pc_grams NUMERIC(8, 2), -- Nominal weight for scrap & yield reconciliation
    unit_rate NUMERIC(10, 2) NOT NULL CHECK (unit_rate >= 0),
    CONSTRAINT chk_dispatch_not_exceed CHECK (quantity_dispatched <= quantity_ordered)
);

-- 4. External Job Work Polishing Batches
CREATE TABLE job_work_batches (
    batch_id SERIAL PRIMARY KEY,
    item_id INT NOT NULL REFERENCES order_items(item_id) ON DELETE RESTRICT,
    contractor_name VARCHAR(100) NOT NULL,
    weight_sent_kg NUMERIC(10, 3) NOT NULL CHECK (weight_sent_kg > 0),
    pieces_received INT DEFAULT 0 CHECK (pieces_received >= 0),
    scrap_weight_kg NUMERIC(8, 3) DEFAULT 0.000,
    batch_status VARCHAR(20) DEFAULT 'WITH_CONTRACTOR' CHECK (
        batch_status IN ('WITH_CONTRACTOR', 'RETURNED_FULL', 'DISCREPANCY_FLAGGED')
    ),
    sent_date DATE DEFAULT CURRENT_DATE,
    received_date DATE
);

-- 5. Split Dispatches & Transport Tagging
CREATE TABLE dispatch_records (
    dispatch_id SERIAL PRIMARY KEY,
    order_id INT NOT NULL REFERENCES orders(order_id) ON DELETE RESTRICT,
    dispatch_date DATE NOT NULL DEFAULT CURRENT_DATE,
    vehicle_lr_number VARCHAR(50),
    dispatched_by VARCHAR(50) NOT NULL
);

CREATE TABLE dispatch_items (
    dispatch_item_id SERIAL PRIMARY KEY,
    dispatch_id INT NOT NULL REFERENCES dispatch_records(dispatch_id) ON DELETE CASCADE,
    item_id INT NOT NULL REFERENCES order_items(item_id) ON DELETE RESTRICT,
    quantity_shipped NUMERIC(10, 2) NOT NULL CHECK (quantity_shipped > 0)
);
